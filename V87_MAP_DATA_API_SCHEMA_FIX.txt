KB Market Survey V87 — Map Data API Schema Fix

Root cause
----------
The deployed map page loaded correctly, but /api/map/data failed because the
web API queried province, district, commune, and village attributes that were
missing from the current KoboSubmission SQLAlchemy model.

Fixes
-----
1. Restores province, district, commune, and village model columns.
2. Automatically adds the missing Railway PostgreSQL columns and indexes.
3. Adds real Open Movement Map and Open Movement Dashboard buttons to /start.
4. Fixes Movement Score filter values so they match the API's numeric ranges.

Deploy
------
unzip -o KB_Market_Survey_V87_MAP_DATA_API_SCHEMA_FIX.zip -d .

python -m py_compile \
  app/db/models.py \
  app/db/database.py \
  app/bot/handlers.py \
  app/bot/run_bot.py \
  app/main.py \
  app/web/router.py

git add \
  app/db/models.py \
  app/db/database.py \
  app/bot/handlers.py \
  app/bot/run_bot.py \
  app/main.py \
  app/web \
  app/reports/excel_report.py \
  tests/test_v87_map_api_schema_and_start_buttons.py \
  V87_MAP_DATA_API_SCHEMA_FIX.txt

git commit -m "Fix movement map data API schema"
git push origin main

After Railway becomes Active
----------------------------
1. Send /start to the bot and use the two buttons.
2. Open /map using the secure viewer link.
3. The startup migration adds the four missing columns automatically.
