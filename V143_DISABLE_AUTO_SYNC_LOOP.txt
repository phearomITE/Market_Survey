KB MARKET SURVEY V143 - DISABLE REPEATING FULL KOBO SYNC
========================================================

The Railway log showed:

Auto Kobo sync enabled: every 60 seconds
Kobo fast fetch: dealer-filter=ALL date=ALL
Auto sync failed: Kobo fetch exceeded 35s after 20 pages and 2000 rows

Cause
-----
Railway still had AUTO_SYNC_ENABLED=true. That environment variable overrides
.env.example. The bot therefore downloaded all historical Kobo pages every
minute. The dataset is now larger than 2,000 rows, so it reached the safety
limit, failed, waited 60 seconds, and repeated.

V143 fix
--------
1. The bot never starts the repeating full-history synchronization loop, even
   if an old Railway AUTO_SYNC_ENABLED=true variable remains.
2. Report, summary, raw movement, and export commands continue to use the fast
   date-filtered Kobo path from V142.
3. /sync_kobo now refreshes today's submissions only and has a 50-second
   command deadline.
4. /alert_submit continues to read today's Kobo metadata directly.

Railway variables
-----------------
AUTO_SYNC_ENABLED=false
AUTO_SYNC_BEFORE_REPORT=false
COMMAND_TIMEOUT_SECONDS=55
KOBO_FETCH_DEADLINE_SECONDS=35
KOBO_REQUEST_TIMEOUT_SECONDS=15
KOBO_CACHE_TTL_SECONDS=30
PNG_RENDER_TIMEOUT_SECONDS=18
