V135 - ALL FEATURES USE CURRENT KOBO DEALER/DATE DATA
=====================================================

Root cause fixed
----------------
The bot treated a non-empty PostgreSQL result as complete. On 2026-08-01 the
database contained only 17 CA7 submissions while Kobo contained 1,650 rows.
Therefore /raw_movement, /export, /summary and several dealer reports silently
generated incomplete files.

New rule
--------
Every report/export/alert command reads the requested report date directly
from Kobo. PostgreSQL is no longer the source for these Excel outputs.

Dealer filtering
----------------
Kobo is filtered server-side by report date only. Dealer codes are normalized
to uppercase and filtered locally. This supports old and new XLSForm versions
whose stored dealer choice values may use different letter case.

Covered features
----------------
- /report DEALER GT DATE
- /report DEALER HORECA DATE
- /report_multi ... DATE
- /report_today DATE
- /summary GT DATE
- /summary HORECA DATE
- /raw_movement DATE
- /export DATE
- /export movement_multi DATE...
- /alert_submit 10
- /alert_submit 20
- /sync_kobo (current Cambodia date)

Performance
-----------
- Uses lightweight in-memory rows instead of SQLAlchemy ORM relationships.
- Summary builds only the products needed for summary movement.
- Alert builds metadata only.
- Selected-dealer reports build metrics only for requested dealers.
- Excel-only mode removes PNG, map, and dashboard waiting.
- Daily export does not reload the stale PostgreSQL wide table.
