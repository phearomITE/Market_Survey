KB Market Survey V75 — Railway asyncio event-loop fix

WHY THE EMPTY COMMIT DID NOT FIX IT
-----------------------------------
git commit --allow-empty only triggered another deployment. It did not change
app/bot/run_bot.py, so Railway ran the same broken code again.

ROOT CAUSE
----------
python-telegram-bot Application.run_polling() calls asyncio.get_event_loop().
On Python 3.12, the movement-map Uvicorn/uvloop server can change the global
event-loop policy, leaving MainThread without a current loop.

SAFE FIX
--------
The patch changes only app/bot/run_bot.py:
- removes app.run_polling(...)
- uses asyncio.run(_run_application(app))
- manually initializes, starts, polls, and shuts down the Telegram app
- preserves map/dashboard startup, all commands, auto Kobo sync, and callbacks
