KB MARKET SURVEY V142 - ONE-MINUTE COMMAND FIX
================================================

Root cause fixed
----------------
The report command was waiting for a complete Kobo -> PostgreSQL synchronization.
That sync downloads every submission and writes many product/competitor rows for
each outlet. Kobo requests could wait 120 seconds, sync waits allowed 180-240
seconds, and LibreOffice could wait another 180 seconds.

V142 behavior
-------------
1. /report, /summary, /raw_movement and /export read the requested Kobo date
   directly; they do not wait for database synchronization.
2. Kobo calls are date-filtered, have a 35-second fetch deadline, and share a
   30-second cache between commands.
3. Every blocking Telegram command has a maximum handler wait of 55 seconds.
4. /report uploads Excel first. PNG gets only the time remaining and cannot
   delay the Excel file.
5. /report_multi and /report_today are Excel-only so bulk PNG conversion cannot
   block the bot.
6. /alert_submit 10 and /alert_submit 20 read current Kobo metadata directly.
7. Automatic heavy database sync is disabled by default. /sync_kobo remains a
   manual command and also returns a timeout message instead of hanging.

Important Railway variables
----------------------------
AUTO_SYNC_BEFORE_REPORT=false
